## Conceptual Model (Implemented on Main)

### The Semantic Distinction

```
Validator warns (same composer + title) → Validator finds potential duplicate
  ↓
Authority classifier examines evidence:
  - Catalogues (different WAB/opus? → background_suspicion)
  - MusicBrainz IDs (same MBID? → confirmed_duplicate; curator_review_required: true)
  - Relationships (version_of? → catalogue_conflict; curator_review_required: false)
  - Sufficiency: determines curator_review_required: bool
  ↓
If curator_review_required == false:
  → **background_suspicion** (trusted data signal)
  → Visible in report; non-blocking
  → Not curator work; does not fail CI or create Issues
  → Only actionable if explicitly activated via --identity-gate-id
  ↓
If curator_review_required == true:
  → Candidate for curator review
  → Becomes actionable ONLY if explicitly activated via --identity-gate-id
  → Then escalated to curator workflow
```

- Major validator refactor
- Data model changes

**What WAS needed** (now on main):

### Issue #151: Phase 2 Scope

## 2. The Root Problem

The tooling conflates five different things:

| Signal | Status | Should Be | Was Being Treated As |
|--------|--------|-----------|-----|
| Curator decision (Bruckner) | ✅ Decided | Background signal | Curator work |
| Background observation (Bach 0.91) | ⏳ Unactivated | Research first | Curator work |
| Missing data (Hindemith) | ⏳ Incomplete | Research queue | Merger queue |
| Data error (Stravinsky K 066) | ❌ Bug | Fix + prevent | Duplicate candidate |
| Consequential decision (Prokofiev) | ❓ Unresolved | Curator task | Mixed in with others |

**Result**: All generate equivalent DUP-* warnings with no classification.

---

## 3. The Solution Architecture

```
Validator DUP-* warning
  ↓
Authority classifier 
  → Examine evidence (catalogues, MBID, relationships)
  → Classify: confirmed_duplicate | distinct_works | catalogue_conflict | needs_authority_review
  → Assess: curator_review_required?
  ↓
If NO curator review required
  → background_suspicion
  → Visible; non-blocking; no Issue
  ↓
If YES curator review required
  → ONLY becomes work if explicitly activated
  → Use --identity-gate-id to promote to action_required
```

**This architecture is now implemented on main.**

---

## 4. Decision Table (Reference)

| Scenario | Classification | Action | Implementation |
|----------|---|---|---|
| Same composer, same title, **different catalogues** | `distinct_works` | No action; preserve | Classifier + Principle 9 |
| Same composer, same title, **same catalogue** | `confirmed_duplicate` | Fix data | Classifier + data review |
| Same composer, 0.91 title-similarity, **no catalogues** | `needs_authority_review` | Research phase → background | Classifier + Principle 16 |
| Same title, **different opus/WAB** | `distinct_works` | Preserve decision | Classifier + work relationships |
| No expert evidence; no resolution path | `background_suspicion` | Visible; defer until activation | Classifier + Principle 16 |
